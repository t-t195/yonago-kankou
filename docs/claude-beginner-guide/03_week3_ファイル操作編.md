# Week 3. ファイル操作編 — Excel・PDF・Word を読ませる

## この章で到達するゴール

- iPhone から Excel・PDF・Word・画像ファイルを Claude に添付できる
- 添付したファイルに対して、要約・集計・論点抽出を依頼できる
- **Projects 機能** を使って、コンサル案件ごとに情報を蓄積できる
- データ分析依頼の書き方テンプレを3種持っている

所要時間：1週間（1日20分 × 7日）

---

## 3-1. ファイルを添付する基本操作

### 手順（iPhone）

1. Claude アプリを開き、チャット入力欄の **左側にある ＋ マーク（またはクリップアイコン）** をタップ
2. 次の選択肢が出る
   - **「写真・動画」** → カメラロールから選ぶ
   - **「ファイル」** → iCloud Drive や Dropbox から選ぶ
   - **「カメラ」** → その場で撮影
   - **「ドキュメントをスキャン」** → 紙書類を読み取り
3. 添付したいファイルを選ぶ
4. 入力欄にファイル名が表示されたら、質問文を打って送信

### 添付できるファイル種類

| 種類 | 拡張子 | 使いみち |
|------|--------|---------|
| Excel | .xlsx / .csv | 売上・在庫・顧客リストの集計 |
| Word | .docx | 規程・マニュアル・議事録の要約 |
| PDF | .pdf | 契約書・会議資料・論文の読解 |
| 画像 | .jpg / .png | ホワイトボード写真・手書きメモのテキスト化 |
| テキスト | .txt | 長文メールやログの解析 |

### ⚠️ 注意：ファイル上限

- 1回のメッセージで添付できるファイル数には上限があります（10〜20個程度）
- 1ファイルあたり 30MB 程度が実用上の上限
- Excel で**マクロ入り**（.xlsm）は添付できないことがあります。.xlsx で保存し直してください

## 3-2. Excel を読ませて集計・分析する

### 実例1：売上サマリ作成

**添付ファイル**：`2026_Q1_売上.xlsx`（支店別・商品別の売上シート）

**プロンプト例**
```
あなたは経営企画のデータアナリストです。
添付の Q1 売上データから、以下を出してください。

1. 支店別の売上トップ3（金額付き）
2. 前年同期比が最も伸びた商品カテゴリ
3. 「要注意」な落ち込み項目（3件）
4. 部長向け1分スピーチ用の要約（100字）

出力は Markdown の表と箇条書きで。
```

### 実例2：顧客リストのクレンジング

**添付ファイル**：`顧客マスター.csv`

**プロンプト例**
```
あなたはデータクレンジングの専門家です。
添付の顧客リストから以下を検出してください。

 ・重複疑い（社名の表記ゆれ）
 ・電話番号が桁違いの行
 ・メールアドレスの形式が不正な行

検出結果は「行番号／問題／推奨アクション」の表で。
修正版ファイルの再生成はしなくて良いです。
```

### 💡 ヒント
- Claude は Excel の**数式**までは再現しないことがあります。**数字の値**を読み取って回答します
- グラフそのものの作成は苦手です。代わりに「どんなグラフが効果的か」を提案してもらい、自分で作るのが効率的です

## 3-3. PDF の会議資料・契約書を読ませる

### 実例1：長い会議資料を 5 分で把握

**添付**：`役員会_議案資料_2026-04.pdf`（50ページ）

**プロンプト例**
```
あなたは役員秘書です。
添付資料を、部長（事前読込なし）が5分で把握できるように要約してください。

出力：
 1. 全体像（3行）
 2. 決定を要する論点（最大5つ、重要度順）
 3. 資料内で根拠が弱いと感じた箇所（ページ番号付き）
 4. 事前に準備すべき質問 3つ
```

### 実例2：契約書のリスク確認

**添付**：`業務委託契約書_ドラフト.pdf`

**プロンプト例**
```
あなたは企業法務の専門家です。
添付契約書のうち、委託側（当社）にとって不利な条項を5つ抽出してください。

各項目：
 ・条項番号とタイトル
 ・なぜ不利か（1文）
 ・修正文案

⚠️ 重要：不明・曖昧な箇所は【要弁護士確認】と明記してください。
あなたの回答だけで最終判断はしません。
```

### ⚠️ 注意
- 法律・医療・税務の最終判断を AI 任せにしないでください
- 「不明な場合は『不明』と答えて」と毎回書く癖をつけると、嘘回答（ハルシネーション）が減ります

## 3-4. 画像・写真を読ませる

### 実例：ホワイトボード写真のテキスト化

**添付**：会議で撮ったホワイトボード写真

**プロンプト例**
```
添付の写真は、会議で使ったホワイトボードです。
書いてある文字と図を、以下の形式で構造化してください。

 ・タイトル
 ・議論の流れ（箇条書き）
 ・決定事項（あれば）
 ・次アクション（担当者名があれば付記）

読めない字は【判読不能】と書いてください。
```

### 💡 ヒント
- 手書きメモ・名刺・看板・スライドのスクショ…どれも高精度で読みます
- 「この図を言葉で説明して」という依頼も可能です（盲目の同僚にメールする想定で、などと伝えるとより丁寧になります）

## 3-5. Projects 機能 — 案件ごとに情報を蓄積する

**Projects（プロジェクト）** は、複数の会話・ファイルをひとつの「案件箱」にまとめられる機能です。
コンサルとして複数顧客を抱えるあなたには、**最重要機能** です。

### Projects 作成手順

1. 画面左上の **三本線（≡）** をタップ
2. **「Projects」** をタップ
3. 右上の **＋ マーク** で新規作成
4. プロジェクト名を入力
   - 例：「A社_業務改善_2026Q2」
5. **「Project knowledge」** 欄に、その案件共通の情報を貼る
   - 顧客プロフィール（業種・規模・担当者）
   - 過去の提案書の要点
   - 守るべき前提（守秘義務、使える予算 etc.）
6. **「Instructions」** 欄に、その案件での Claude の振る舞い方を書く
   - 例：「あなたはこの案件専属のコンサルタントです。返答は常に社名と担当者名を意識し、専門用語は避け、300字以内にまとめてください。」
7. **「Create project」** で完成

### 使い方

- その案件の会話は、すべて同プロジェクト内で開始する
- Claude は毎回、Project knowledge を自動で参照してくれる
- ファイル添付もプロジェクト単位でまとめておける

### 💡 ヒント
- 顧客名を直接プロジェクト名に入れる場合、**匿名コード（A社、B社）** で運用すると情報漏洩リスクが下がります
- Project knowledge は 200,000 文字くらいまで入ります。ミニ社内 Wiki として使えます

## 3-6. データ分析依頼の書き方テンプレ 3 種

### テンプレ①：要約分析

```
添付データの【期間】における、以下を整理してください。
 1. 全体サマリ（3行）
 2. 気づき3つ
 3. 意思決定者への提言1つ
```

### テンプレ②：比較分析

```
添付データから、【軸A】と【軸B】を比較してください。
 ・差が大きい上位5項目
 ・統計的に有意かの定性判断（小サンプルの可能性も指摘）
 ・経営会議で示す際のメッセージ1文
```

### テンプレ③：異常検知

```
添付データから、以下を検出してください。
 ・通常範囲から外れる値（平均±2σ相当）
 ・連続で悪化している指標
 ・「本来整合すべきだが矛盾している」数字

出力は「項目／数値／理由」の表形式で。
```

## よくあるつまずき Q&A

**Q1. Excel を添付したのに「読めません」と言われます**
A. 以下を確認してください。
- .xlsm（マクロ入り）→ .xlsx で保存し直す
- パスワード付き → パスワードを外す
- ファイルサイズが大きすぎる → 不要シートを削除して軽量化

**Q2. 添付した PDF の数字が間違って読まれます**
A. PDF の種類によっては、文字が画像化されていて読み取り精度が落ちます。可能なら Word や Excel の元ファイルを添付してください。

**Q3. Project knowledge に書いた情報が無視されています**
A. そのプロジェクト**内**で新規会話を作ったか確認してください。プロジェクト外の通常チャットでは参照されません。

**Q4. 顧客の個人情報を貼って良いですか？**
A. 会社のポリシー次第です。不安なら **匿名化**（氏名→「顧客A」、金額→「XXX万円」等）してから貼るのが安全です。

# SEO / AIO skill

## 目的
検索エンジンとAI検索（AI Overviews/ChatGPT等）の両方から発見・引用される状態を作る。

## 方針（重要）
AI検索対策の本筋は通常のSEO＝**良質なコンテンツ + 構造化データ + E-E-A-T**（Google 2026年5月見解）。小手先の単独施策（llms.txt等）に時間をかけない。施策の鮮度に注意し、不明点は必ずWebSearchで最新動向を確認してから実装する。

## 入出力
- 入力: 実装済みサイト（`site/`）、`06_content.md`（メタ情報原稿）
- 出力: `projects/<案件名>/08_seo-aio.md`（チェック結果）+ サイトへの修正実装

## 手順
1. `templates/08_seo-aio-checklist.md` をコピーし、現状を全項目監査（未実装/実装済み/対象外）
2. 基本メタ実装: title・description（06の原稿どおり）・canonical・OGP
3. 構造化データ実装: Organization/LocalBusiness・WebSite・FAQPage・業種固有スキーマをJSON-LDで。実装後に**JSONパース検証 + リッチリザルトテスト**
4. コンテンツ品質監査:
   - 比較・料金情報が表になっているか（グラフ・画像内テキストはAIに読めない）
   - FAQが結論ファーストか
   - E-E-A-T（実名運営者情報）があるか → 不足は06に差し戻し
5. テクニカル: sitemap.xml / robots.txt / 見出し階層 / Core Web Vitals
6. 公開後タスク（Search Console登録・GA4・ビジネスプロフィール）を10の手順書に転記
7. チェックリスト全項目の合否と、対象外にした項目の理由を報告

## 品質基準
- 全構造化データがエラーなしで検証を通る
- 「対象外」項目に理由が書いてある（黙ってスキップしない）
- 費用が発生する施策（有料ツール等）を勝手に前提にしない

## アンチパターン
- キーワード詰め込み・隠しテキスト等の旧式スパム手法
- 構造化データと画面表示の内容不一致（ガイドライン違反）
- 「AI対策」と称した根拠不明の施策を検証せず追加する

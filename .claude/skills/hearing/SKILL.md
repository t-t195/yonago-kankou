# ヒアリング・要件定義 skill

## 目的
発注者の頭の中にある情報を引き出し、以降の全フェーズの「正」となるプロジェクトブリーフを作る。

## 入出力
- 入力: 発注者の回答（対話・メモ・既存資料）。引数で案件名を受け取る
- 出力: `projects/<案件名>/00_hearing.md`、`projects/<案件名>/01_brief.md`

## 手順
1. `projects/<案件名>/` を作成し、`templates/00_hearing-sheet.md` をコピー
2. ユーザーから得られた情報をシートに転記。**埋まっていない項目を一覧化して提示**し、回答を依頼する
3. 重要項目（C-11: CV目標 / C-13: ターゲット / A-5: 選ばれる理由）が曖昧なら、具体例を出して深掘り質問する
   - 悪い回答例:「いい感じに」「みんなに見てほしい」→ 必ず1つに絞らせる
4. 「わからない」回答に印を付け、リサーチ課題として `02_research.md` 用に控える
5. 回答の矛盾を検出して確認リストを提示（例: ターゲットと参考サイトのトーン不一致）
6. 全回答を `templates/01_project-brief.md` の型に構造化し、承認を依頼する

## 品質基準
- CV(一次目的)が1つに絞れている
- KGIが数値になっている（「増やしたい」はNG）
- スコープの「含まない」が明文化されている

## アンチパターン
- 回答が空欄のまま想像で埋める（→必ず【要確認】マークを残す）
- ヒアリング項目を一度に全部投げる（→重要度A→C→B→Dの順に小分けで聞く）

# 構築 skill

## 目的
承認済みの設計(04/05)と原稿(06)を**差分ゼロ**で実装する。構築フェーズでの創作はしない。

## 入出力
- 入力: `04_wireframe.md`、`05_design-system.md`、`06_content.md`、`07_build-spec.md`
- 出力: `projects/<案件名>/site/` 一式

## 手順
1. `templates/07_build-spec.md` をコピーし技術選定を確定。判断軸は**更新者のスキルと運用コスト**（自分が作りやすいかではない）
2. **費用が発生する選定（有料API・有料プラグイン・サーバー）は実装前にユーザーへ確認**。無料代替があるなら先に提示（例: Google Maps JS API→無料iframe埋め込み）
3. 実装順: ①デザイントークン(CSS変数) → ②共通レイアウト → ③セクション上から → ④構造化データ・メタ → ⑤計測タグ位置
4. コーディング規約（07-3）厳守: セマンティックHTML / 画像width・height / lazy / alt / フォーカス可視
5. 原稿(06)からテキストを**コピペで**反映（タイプし直さない＝改変防止）
6. 未確定箇所は `【要編集】` とHTMLコメント `<!-- TODO: -->` で機械検索可能にする
7. パフォーマンス予算（Lighthouse 90+ / LCP 2.5s / 画像200KB）を実装中に随時確認
8. 完了時にセルフチェック: 06との全文diff、04との構造差分、エラーゼロ

## 品質基準
- 07の「完了の定義」4項目を満たす
- 外部依存が仕様書に書かれたものだけ（勝手にCDNを追加しない）
- 仕様と実装に差異が出たら、**仕様書側を更新して承認を取ってから**実装する

## アンチパターン
- 実装しながらコピーを「改善」する（→06に差し戻して承認を取る）
- Tailwind CDN版・jQuery等を本番に入れる
- 動くからOKでアクセシビリティを省略する

# 構成・ワイヤーフレーム skill

## 目的
リサーチの訴求優先順位を「ページとセクションの順番＝説得のシナリオ」に翻訳し、レイアウトまで確定する。

## 入出力
- 入力: `projects/<案件名>/01_brief.md`、`02_research.md`（承認済み）
- 出力: `projects/<案件名>/03_structure.md`、`04_wireframe.md`

## 手順
1. ワンページ(LP)か複数ページかを判断し、理由を明記（判断軸: コンテンツ量・更新頻度・SEOで狙うKW数）
2. 構成パターンを選定（課題解決型=PASONA系 / ブランド型 / 比較検討型）し、採用理由を書く
3. セクション構成表を作成。**ペルソナの不安・疑問(02-5)を全件、どこかのセクションに割り当てる**。割り当て先のない不安が残ったらセクションを追加する
4. CV導線設計: メインCTA文言・出現頻度（2画面に1回）・フォーム項目の最小化
5. `04_wireframe.md` にモバイルファーストでASCIIワイヤーを描く（装飾の話はしない）
6. インタラクションはHTML標準優先（`<details>`等）でJS要否を明記
7. WFレビュー観点（04の5項目）でセルフチェックしてから承認依頼

## 品質基準
- ファーストビューだけで「誰向けの何のサイトか」が答えられる構成
- 各セクションに「読者の心理」と「解消する不安」が書かれている
- 「削れる要素を3つ探す」を実施した形跡がある

## アンチパターン
- 競合サイトの構成をそのまま写す（リサーチの意味がない）
- セクションを足して解決しようとする（迷ったら削る）
- WFの段階で色やフォントの話を始める
